# NIKKE 更新头图排查与修复

Codex · 2026-11-04。按所有者要求排查最新更新缺图，全部使用 `logs/nikke-artwork-20261104/` 隔离目录，没有读取、修改真实 `data/`，没有更改版本号或发布。

## 已确认的原因

1. [GameKee 国际服活动列表](https://www.gamekee.com/nikke/huodong/19) 实际提供新活动图片。10 月 29 日这一批取到 11 条记录，11 条均有独立图片地址，包含 MARIA-n、FULL BURST DAY、签到、活动通行证等。
2. [10 月 29 日更新公告](https://www.gamekee.com/nikke/725772.html) 的元数据能读取，但其 `api-cdn.gamekee.com` 正文请求在本次复测返回 HTTP 567。旧流程先尝试正文，再下载图片；网络层将这些子域合并为 GameKee 站点预算，正文失败引起的冷却会阻断后续图片请求。浏览器能查看公告，不代表程序的正文请求也能通过。
3. 活动 7994 的图片引用 GameKee 共享编辑器 `/wiki2.0/pro/215/images/`，旧白名单只允许当前 Wiki 的图片和共享视频路径，因此这张图片会被静默跳过。
4. 代码复核另发现：缓存图片也被计入本轮新图片额度，同一失败 URL 可能被重复尝试；不一定触发当前这批缺图，但会影响后续补图，已加入回归修复。

## 修复

- 元数据和可复用正文照常读取；只有需要额外请求正文 CDN 的公告延后处理。日期先发布，卡片头图先下载并保存，再尝试正文。若正文读取成功，再重新编译并保存公告精确时间及段落头图。
- 保存的日期和图片经过原完整校验；重编译复用已读元数据和已下载图片，不额外重复读取，也不重置同轮图片额度。
- 正文 HTTP 567 记录 24 小时不重复探测。站点冷却、暂停、每小时和每轮配额、请求间隔均未修改；没有绕过访问验证。
- 允许来源活动明确引用的 GameKee 共享编辑器 215 图片。其他主机、路径穿越、SVG、任意其他 Wiki 目录仍拒绝。
- 缓存图片不占新下载次数；同一 URL 本轮最多尝试一次；“有意稍后补图”不计下载失败，待补和被拒绝的图片另有状态提示。
- 未核对的新活动仍用卡片预计时间，不把图片可用等同于公告时间已确认。活动 ID 和个人状态的兼容规则不变。

## 验证

- `test_gamekee.py` 19 项通过，完整后端 322 项通过。模拟网络明确验证：两张图在第一次 567 之前成功保存；随后站点仍冷却；后续同步不会反复探测被拒绝的正文 CDN。
- 另测正文正常返回时，只读一次元数据，补读后公告精确截止、原卡片 ID 和图片均保留；图片预算和失败去重有单独回归。
- 通过项目原有限流器真实下载两张图片：活动 7984（1253 目录，147481 字节）、活动 7994（共享 215 目录，189571 字节），均验证为 PNG，无下载错误。
- 原 NIKKE 浏览器回归通过；两张真实图片在隔离页面的时间轴和详情中均解码成功，无浏览器运行时错误。证据为 `live-images-result.json`、`live-browser-result.json`、`latest-heads-timeline.png`，后端测试日志为 `unit-all.log`。

数据和图片仍来自原 GameKee 社区来源，归属与非商业声明不变；固定测试样本只保存公开的活动事实和图片 URL，没有将新图片加入项目分发素材。

项目目录中的程序需要重启后再同步 NIKKE。既有发布 ZIP / EXE 副本没有自动替换；此前已暂停的站点也不会被本次修复擅自解除暂停。

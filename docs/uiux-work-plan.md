## 3. C0 首次交接必须确定的规则

1. **接口形状**：明确快照、订阅取消、具名操作、结果和异常；原始可变状态、通用任意请求入口不直接成为外壳 API。渲染是否可挂载、挂在哪里、谁拥有事件监听，逐项写清。接口完成后由双方记录接收情况，再接真实数据。
2. **日期与筛选**：保留现有默认行为作为兼容基线，逐字段记录切游戏、切视图、今天、全览、清除筛选的效果。新流程需要改变默认行为时，单独列出前后差异，不在外壳中另写一套。
3. **返回与草稿**：详情和编辑按直接来源返回；保存失败保留输入，未保存离开先处理草稿。网页弹层恢复来源；安卓返回先处理草稿和最上层抽屉／子页面，再处理一级页面。一级页面历史、深链接和进程重启后的恢复方式在路由接入前补齐用例。
4. **状态保存**：游戏组合、个人记录、主题及现有共享聚焦沿用原持久化语义；滚动、来源栈及未提交草稿先按当前会话管理，不在本轮引入新的备份格式。页面切换和轮询不清空正在编辑的内容。
5. **统计与同步**：共用活动 ID、阶段关闭及兑换节点、去重和时区规则。手机月历采用已确认的整格填充及右下角数量。下拉只增加手动入口，自动保守复查、缓存、冷却和提醒范围继续沿用原规则。

## 4. 安卓首轮实施边界

采用提案中的近期／日历／计划／我的四页组织，默认近期页。首轮收起手机上的桌面目录、模块编辑和高级导出入口，保留底层能力及用户配置；不承诺本轮完成系统分享或后台通知。

左滑完成、右滑收藏按提案作为可调整的初始方案，必须同时提供按钮和撤销。窄屏、大字号或数据不足时以可读可操作为先，“首屏五条”作为指定设备和标准字号的布局目标，不为满足数量裁掉标题、操作或无障碍内容。

主题与外观复用现有语义颜色。安卓外壳标记只选择呈现，不作为 API 或原生桥授权。宿主来源限制和会话保护继续有效。

## 5. 测试与交付

- 两端先使用隔离、离线、日期固定的样本；不读写真实 `data/`，不反复联网同步。
- Codex 先核对已有 `e2e-architecture`、`e2e-bulletin-artwork` 失败报告，记录独立基线；未经复现不把报告归因于日期或另一端改动。
- Claude 的交接列出文件、接口依赖、测试命令及结果、设备证据、已知问题；Codex 的复核另记结论，保留未验证项。
- 需要改共享接口时，先写明变更及兼容方式；由 Codex 修改共享文件，Claude 更新消费方，避免双方同时动同一文件。
- 本轮任务分配不包含 Git 推送或 Release。APK 测试包在功能和兼容检查后交付，公开发布另按所有者指示执行。

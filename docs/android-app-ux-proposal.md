## 2. 设计原则

1. **一屏一件事**：每个主页面只回答一个问题。近期页回答“马上要截止什么”，日历页回答“这段时间的排期”，计划页回答“我打算什么时候玩”，我的页回答“设置和状态”。
2. **内容先于控制**：顶栏只保留标题、游戏范围和最多两个图标；筛选、排序和视图细节收进抽屉。首屏至少能看到 5 条活动。
3. **触屏优先**：点一下进详情，滑动做快捷操作，长按出更多操作；所有点击区域至少 44px；能用拖动的地方，也一定有表单或按钮可以完成同样的事。
4. **系统一致**：返回键、下拉刷新、底部抽屉、提示条（带撤销）、系统通知、跟随系统深色模式、状态栏颜色。
5. **保留游时的视觉身份**：直角、黑白对比、局部亮黄、等宽数字。主题系统保留，但手机上只提供预设，不提供令牌级编辑。
6. **业务规则不变**：活动 ID、个人数据格式、插件 API、限流和保守复查都不动；改的只是安卓端的界面层。

├─ 日历          顶部分段：时间轴 | 截止月历

│                截止月历：紧凑月格 + 每天的密度条，点日期从底部弹出当天明细
├─ 计划          个人计划列表 + “新建计划”按钮；新建用底部表单，也可以去时间轴拖选
└─ 我的          同步状态卡片；游戏、同步与网络、备份与恢复、提醒、外观、时区、关于
全局
├─ 顶栏“游戏范围”按钮 → 底部抽屉：全部 / 自选组合，每款游戏一行（带图标和来源）

├─ 活动详情 = 整页（返回箭头）：头图、标题与状态标签、时间卡（开始/截止/倒计时）、可折叠的说明与单条提醒；

└─ 提示条：“已标记完成 / 已收藏”带撤销；同步结果“新增 2 · 更新 1”

## 4. 关键交互

- **近期页列表**：左滑标记完成，右滑收藏，都带撤销；长按弹出操作菜单（收藏、完成、安排、提醒、来源原文）；点击进入详情。
- **同步**：下拉刷新同步当前游戏范围。同步时顶栏下方出现进度条和当前阶段文字，比如“正在读取公告”；“等待站点间隔”这类等待只写文字，不做假进度。完成后用提示条显示结果。限流和冷却规则不变，冷却期间下拉只提示还要等多久。
- **返回键**：依次关闭抽屉，关闭详情，回到上一个标签，最后退出应用。由 WebView 内的路由提供 `back()`，`MainActivity.onBackPressed` 先问它。
- **离线**：顶栏下方一行状态说明；同步失败时保留缓存，并写明“上次成功：…”。
- **动效**：页面推入 200ms，抽屉上滑 220ms，列表重排沿用现有 FLIP；跟随系统的“减少动画”设置。

## 5. 实现方式（继续复用网页，只加安卓外壳层）

- **外壳层**：新增 `web/shell/`（`shell.css`、`shell.js`），只在 `<html data-shell="android">` 时加载和生效，桌面和网页完全不受影响。`MainActivity` 加载 `/?shell=android`，或者在页面加载时注入这个标记。
- **路由**：hash 路由 `#/upcoming`、`#/calendar/timeline`、`#/calendar/month`、`#/plans`、`#/me/...`、`#/event/<id>`。每个路由一个容器，每次压一条历史记录，返回键因此可用。
- **复用**：数据、状态和写入继续走 `/api/*` 和 `PlaytimeWorkspace`；时间轴和月历沿用 `app.js` 的渲染函数。需要 Codex 在 `app.js` 暴露一个小接口，例如 `window.PlaytimeApp = {state, render(view, mount), openEvent, mutate}`，避免外壳层复制业务逻辑。近期列表、抽屉、详情页和“我的”在外壳层里实现，只读状态、调用现有接口。
- **原生配合**（`android/`）：
  - 返回键转交给 `PlaytimeShell.back()`；
  - 状态栏和导航栏颜色跟随主题（JS 桥 `PlaytimeHost.setBars`）；
  - 长按和完成时的触感反馈；
  - 用系统分享和系统浏览器；
  - 以后做系统通知提醒。
- **测试**：`tests/e2e-android-shell.cjs` 用手机模拟和真实触摸事件，覆盖导航、返回、下拉同步（模拟）、滑动操作、抽屉和详情；`android/tools/device-check.cjs` 在设备上再验证一遍。

## 6. 分阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 骨架 | 外壳层；底部导航四个页面；顶栏（标题 + 游戏范围 + 筛选）；返回键；隐藏网页页头、侧栏和桌面入口；近期页列表与“下一个截止”卡片 | 首屏能看到 ≥5 条活动；返回键逐层退出；桌面和网页的回归测试不变 |
| P1 操作 | 活动详情整页与底部操作栏；滑动和长按操作；带撤销的提示条；游戏范围抽屉和筛选抽屉；下拉同步与阶段提示 | 收藏、完成都能撤销；同步只在用户下拉时发生，限流不变 |
| P2 页面 | 日历页（时间轴 + 紧凑截止月历与当天抽屉）；计划页（列表 + 新建表单）；“我的”的各项设置页 | 月历一屏放下整月；不进入时间轴也能新建计划 |
| P3 打磨 | 深色模式；触感反馈；系统分享；无障碍朗读顺序；真机和多种屏幕尺寸 | 实体手机验收 |

## 7. 需要确认的事

1. 底部四个标签“近期 / 日历 / 计划 / 我的”是否合适，首页是否默认为“近期”。
2. 手机上去掉版本选择、日期全览、专注时间轴、模块布局编辑和导出，可否接受。
3. 滑动方向：左滑完成、右滑收藏，还是反过来。
4. 分工建议：小克负责 `web/shell/` 和 `android/`；Codex 负责在 `app.js` 暴露接口、负责共享渲染函数的兼容和整体验收。外壳层不修改 Codex 正在编辑的文件。

# 网页任务往返与草稿

Codex · 2026-11-13。对应网页交互分工 C1、C2 网页续作。本文描述源码行为，未表示已经发布安装包或完成设备验收。

## 返回规则

`web/journey.js` 管理当前网页会话的弹窗来源。打开子任务时隐藏来源弹窗，保留它的内容、页签、滚动和触发控件。关闭、Esc 和浏览器后退沿直接来源返回，不再统一跳到计划总览。主任务只显示一个，放弃草稿时另显示小确认框。

| 入口 | 保存计划后 | 取消后 |
| --- | --- | --- |
| 个人计划总览 | 返回总览并定位计划 | 返回原总览 |
| 当天汇总 | 返回该日的“开放活动与计划”页签并定位计划 | 保留原日期及页签 |
| 活动详情 | 返回该活动，显示已保存与“查看计划”入口 | 返回详情并保留备注草稿 |
| 时间轴拖选或计划条 | 返回时间轴，显示计划条 | 返回原时间轴 |
| 无来源的编辑深链接 | 返回日程工作台 | 返回日程工作台 |

来源列表因数据更新而重建时，用活动/计划身份寻找原触发控件，并恢复滚动容器；条目不存在时保留可用的列表或标题焦点。详情来源被同步移除时保留当前内容与草稿，并明确提示已经不在最新日历中。

## 草稿与保存

- 计划、详情的时间校正/备注/开服记录、设置中的主题和布局使用未保存检查。返回时选择继续编辑或放弃；浏览器刷新/离开时请求浏览器自己的未保存确认。
- 保存失败保留字段和错误。计划及详情表单保存期间禁止重复提交和关闭，计划显示“保存中”。
- 新计划每份草稿生成一个 `request_id`；响应丢失后重试沿用它，复用后端已有的去重实现。
- 收藏、完成等操作刷新详情时只保留真正改过的字段。保存一个详情表单不会清除另一个表单的草稿。
- 主题和布局分别应用。如果另一组仍有改动，留在设置页并提示，避免保存主题时丢失布局改动。
- 草稿只在本次页面会话内保留，不新增数据库表或备份格式。页面重新加载后不自动恢复草稿。

弹窗使用同 URL 的临时浏览器历史。后退与关闭使用同一来源规则；浏览器前进不重新打开已保存或已放弃的表单。安卓外壳继续使用自己的路由与返回实现，网页来源栈不写入它的历史。

## 临时定位与日期

从提醒进入时间轴定位会记住原游戏组合、版本、视图、日期窗口、搜索、类型、待定显示和滚动。点击“返回原视图”恢复这些内容；从收件箱进入的同时返回收件箱。返回游戏范围仍走现有工作区写入，不改变提醒配置。

用户主动切换日期、视图、游戏、版本或时间轴天数后，以新操作为准，结束旧定位上下文。定位等待游戏范围请求时，较晚响应不能把新选择的月份改成时间轴。

普通游戏选择沿用原规则：重置搜索和日期窗口，类型等业务筛选继续保留；本轮未加入按游戏永久保存独立视图的功能。有效 `event` 深链接可打开其他游戏的活动详情，关闭后返回入口视图；失效活动/计划给出明确提示。非法日期忽略并沿用可用日期。一次性任务参数使用后移除，刷新不重复启动任务。

## 验证

`tests/e2e-web-journey.cjs` 使用临时数据库、固定日期及虚构 JSON 插件，覆盖嵌套来源返回、长汇总滚动、计划的四类入口、字段保护、保存失败/慢响应/成功响应丢失后的重试、备注与主题草稿、跨游戏定位及重建时间轴的滚动恢复、较晚定位响应、浏览器后退、深链接和 375px 窄屏确认框。

兼容检查包括 `e2e-planner`、`e2e-plan-drawing`、`e2e-uiux`、`e2e-accessibility`、`e2e-stale-poll`、`e2e-focus-queue`、`e2e-timeline-motion` 和 `e2e-shell-source`。可访问性与动效回归中的来源关闭步骤按新返回规则补齐；焦点队列测试固定到样本日期，避免样本全部结束后没有时间轴条目。旧 APK 源码副本复现了原来的日期依赖失败，固定日期后新旧代码均通过。

这些浏览器检查不代替真实讲述人、物理触屏、Windows 原生窗口或安卓键盘验收。插件 API、活动身份、限流、提醒范围和个人数据格式保持原有规则。

2026-11-13 验证结果：325 项单元测试与上述九组浏览器回归通过。宽屏和 375px 确认框已截图复看。源码新增了静态资源映射，运行旧进程时需要退出并重新启动本地程序，再刷新网页。现有 APK/EXE 的交付哈希仍属于上一轮构建，本次未重建安装包。

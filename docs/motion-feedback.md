# 界面反馈动效（更新于 2026-11-05）

Codex 按所有者确认，将 HTML 预览中的时间轴与操作反馈接入正式网页。详情即时打开和关闭，继续显示原头图。桌面气泡贴边收起和展开沿用原实现。

## 使用

- 网页首次显示时间轴时，可见时间条从左向右逐行错峰展开，速度由慢到快，再减速停下。切换筛选时，消失的行短暂淡出，留下的行滑到新位置。展开完整时间轴时，上方模块收起，时间轴向上展开。
- 长按网页时间条后上下拖动。触屏长按活动旁的拖动手柄，也可用键盘 `Alt` + `↑` / `↓`。拖动在同组内生效，保存后切换到“手动排序”，可撤销。收藏优先开启时，收藏行仍在最上方；已折叠或被筛选的活动保留其排序记录。
- 时间轴活动标题旁可收藏和标记完成。收藏置顶有短暂抬升，完成操作提供撤销入口。
- 同步状态使用真实的“读取公告 → 整理日期 → 补充头图 → 完成”阶段。等待请求间隔会显示暂停状态，失败保留缓存；不会用动画假装下载进度。多游戏同时同步显示仍在进行的最早阶段，全部成功才显示完成。
- “个人计划 → 创建个人规划”开启拖选，松开后确认名称、时间与关联。确认后回到时间轴，新计划条短暂显现。保存中及弹窗关闭后重复确认均不会新增第二条计划。
- 提醒收件箱提供“在时间轴定位”。选中活动后滚动并高亮该行，必要时临时显示被过滤或折叠的目标。结束定位后恢复原筛选。
- 网页“设置 → 主题”和桌面“外观 → 界面反馈动效”可选跟随系统、标准、减少、关闭。两端共用 `settings.ui_motion`，重启保留；减少模式只保留短暂透明度变化，关闭模式不播放新增反馈。该设置不改变原有气泡贴边动画。

## 实现边界

网页 `web/motion.js` 与 `web/motion.css` 控制呈现，`web/timeline-order.js` 管理拖动。`workspace.view.manual_order` 存储用户的活动顺序，后端通过原 `event_order` 提供排序结果，活动时间和计划继续经各自接口持久化。列表重建后恢复对应按钮焦点，用户已转去其他控件时，慢请求不会抢回焦点。没有变化的轮询不会重播。开场单条约 420ms，错峰步长 34ms；常规位移约 180ms，减少动效约 120ms，画面内最多同时反馈 24 行。

桌面 `desktop/CalendarWindow.Motion.cs` 只处理卡片内排序、同步状态淡入和设置，不改变窗口坐标。原 `CalendarWindow.EdgeAnimation.cs` 保持原样。收藏/完成请求设有重复操作保护，重建后恢复对应操作按钮。

旧设置缺少 `ui_motion` 时默认跟随系统。从源码运行时，重启后端并刷新页面以加载新脚本。
